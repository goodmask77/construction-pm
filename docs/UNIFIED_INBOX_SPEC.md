# 統一收件匣|規格 v1

把所有官方 LINE 帳號的客人對話、與廠商群組的對話集中到 app 一個收件匣:可看、有未讀通知、可指派、可回覆、可標記處理完成,不用再切換每個官方帳號後台。

## 先決定:收件匣放在哪個 app(待張良與阿桑決定)

阿桑的 OPS app 已有「廠商對話」(待回/全部、內場/外場/吧台分類、搜尋、釘選、從 app 回覆直送 LINE 群組),截圖確認於 2026-10-10。為避免兩套收件匣並存:

- **方案 A(建議)**:擴充阿桑的廠商對話,加入三個官方帳號與帳號分頁;本 repo 不重做廠商群組。11 月 ops 合併後資料自然進張良的資料庫
- **方案 B**:在本 repo 重做,並把阿桑的廠商對話搬過來

決定前,CC 只做批次 0 盤點,不實作批次 1–3。盤點加查:廠商群組裡的機器人是阿桑的官方帳號還是 DD,或兩個都在;若兩個都在,先定由誰負責回覆。

## 要串的管道

| 管道 | 類型 | 方式 |
| --- | --- | --- |
| A Beach 客服 | 官方帳號 1:1 | Messaging API webhook |
| GROUN:D 客服 | 官方帳號 1:1 | Messaging API webhook |
| 人才招募(104 導流) | 官方帳號 1:1 | Messaging API webhook;可與 `docs/` 招募流程連動 |
| 廠商 | LINE 群組(DD 在群內) | 沿用 DD 既有 webhook 與廠商綁定群 `lineGroupId` |
| FB/IG 私訊 | Meta | 後續另案,沿用既有 Meta API 串接 |

## 已知限制(寫給所有人看)

1. **個人 LINE 帳號的聊天無法串接**。廠商對話要進 app,必須在有 DD 的群組裡進行;從 app 回覆時,訊息由 DD 發出,不是以個人名義
2. **回覆可能扣訊息額度**:收到訊息後短時間內用 reply 免費;超過時效只能 push,會計入該官方帳號的每月訊息則數。app 回覆框要顯示「這則免費/會扣額度」與本月剩餘
3. **回覆統一從 app 發**:官方帳號後台的手動聊天回覆不一定會進 webhook,混用會造成紀錄缺口;上線後規定一律從 app 回覆
4. **每個官方帳號只有一個 webhook 網址**:改設定前先確認目前是否已接其他系統(訂位、阿桑 OPS app 等);若已被佔用,改用轉發(收到後轉送給原系統)或與該系統協調

## 架構

- 單一接收端點 `api/inbox-webhook.js`,依 webhook 內容的 `destination`(官方帳號 ID)分辨是哪個帳號;各帳號的 channel secret / access token 放環境變數,每個請求都驗證簽章
- 廠商群組訊息由 `api/line-webhook.js`(DD)收到後,另寫一份進收件匣;不改動 DD 既有回答邏輯
- 每則訊息存一筆(帳號、對話、發送者、時間、類型、內容、附件路徑、方向 in/out、由誰從 app 送出);**每個對話各自一筆對話紀錄,不可全部擠在同一個 KV 鍵**(避免 DD 的覆蓋問題重演)
- 圖片、檔案下載後存私有桶,app 用短效網址顯示
- 客人個資(顯示名稱、電話、訊息內容)屬個資:收件匣依帳號設權限,預設 A Beach 客服只給 A Beach 指定人員、招募只給招募負責人

## 頁面

1. **收件匣列表**:上方帳號分頁(全部|A Beach 客服|GROUN:D 客服|招募|廠商),每列標帳號;每個對話一列(帳號標籤、對方名稱、最後一則、時間、未讀數、狀態、負責人);排序:未讀 > 待處理 > 時間
2. **對話頁**:時間軸顯示訊息(含圖片、貼圖、檔案);下方回覆框顯示「免費/扣額度」;常用回覆範本;指派給某人;狀態(新/處理中/已完成);內部備註(客人看不到)
3. **通知**:新訊息即時通知負責人(app 推播或 DD 私訊),超過設定時間未回覆再提醒
4. **設定**:帳號清單與連線狀態、權限、範本、自動提醒時間、額度顯示

## 開發批次

1. **批次 0|盤點(唯讀)**:列出每個官方帳號是否已開 Messaging API、目前 webhook 指向哪裡、聊天模式設定、方案與每月額度;查 LINE 官方文件確認 reply 時效、push 計費、官方帳號後台手動回覆是否進 webhook。回報後由張良決定串接方式
2. **批次 1|只收不回**:接收、存檔、收件匣列表、對話頁、未讀與通知、狀態與指派
3. **批次 2|從 app 回覆**:reply/push 自動判斷與額度顯示、範本、內部備註、未回覆提醒
4. **批次 3|廠商群組**(若採方案 A 則不做,沿用阿桑既有功能):DD 所在的廠商群組訊息進收件匣;從 app 回覆由 DD 發送;叫貨卡片與對話串在同一頁
5. **後續**:FB/IG 私訊;AI 回覆建議(走 AI 中樞,只建議、人按送出)

## 驗收

- [ ] 三個官方帳號各自傳一則測試訊息,都出現在收件匣且帳號標籤正確
- [ ] 同時兩個客人傳訊息,兩邊對話都完整,沒有互相覆蓋
- [ ] 圖片與檔案可在 app 看到,網址為短效
- [ ] 從 app 回覆:時效內顯示「免費」並成功;逾時顯示「會扣額度」並以 push 送達
- [ ] 簽章驗證失敗的請求被拒絕
- [ ] 沒有權限的人看不到該帳號的對話
- [ ] 廠商群組裡的訊息出現在收件匣,從 app 回覆後群組看到 DD 發出的訊息
- [ ] 改接 webhook 後,原本接在該帳號的系統(若有)仍正常
