## 0. 一句話
收件匣對話按「建立點餐單」→ 客人拿到專屬連結自己填（可一人代填全部）→ 店家在 /prep「團體訂餐」核價 → 出兩張圖（01 個人明細計價表／02 品項整合表）傳回客人 → 客人按確認 → 鎖單存檔；付款狀態欄先留好，之後接金流。

## 1. 角色與入口
| 角色 | 入口 | 能做 |
|---|---|---|
| 客人（主辦人／每位同事） | `ground-pm.vercel.app/order/<8碼>`（免登入，連結即授權） | 填姓名＋餐點、改自己那列、主辦人可改全部、看計價圖、按「確認」 |
| 店家（正職／主管） | /prep 新分頁「團體訂餐」＋收件匣對話右上「建立點餐單」 | 建單、核價、補舊品項、設取餐時間、出圖、傳圖、鎖單、改付款狀態 |
| DD | 收件匣 relay 照舊 | 客人問「多少錢」DD 可查 `query_grporder` 回答（第二批） |

## 2. 流程（一單的生命週期）
1. **建單**：收件匣對話 → 「建立點餐單」→ 自動帶客人 LINE 顯示名、對話 convId、帳號（GROUN:D／A Beach）；店家補：客戶名稱（公司）、統編、取餐日期時間、外帶／外送／內用、備註。
2. **發連結**：走現有 sendOut（reply 50 秒內免費，否則 push）。訊息範本：「您好，這是您的點餐連結，大家可以自己填，填好按送出：…」。
3. **客人填單**：手機頁面（LINE 內建瀏覽器開）。左＝菜單（分類 chips＋搜尋），右／下＝「我的餐點」。一列＝一人：姓名、主餐、套餐（是／否）、小點、飲品（冰甜）、單點、備註。套餐規則自動算（§4）。主辦人模式：可貼整段文字（像 Amber 貼的那段）→ AI 解析成列（走 aiCall，路由 `grporder`，低 effort），解析不到的列標「待確認」。
4. **送出**：狀態 `submitted` → 店家鈴鐺＋LINE 私訊負責人（通知鐵則：兩端都發）；客人頁顯示「店家核價中」。
5. **核價**：店家在 /prep 看每列，可：改品項（只能換成最新菜單上的品項，不能手填價格）、合併共用品項（披薩）、加折扣（% 或金額）、填訂金。每次改動留 edits（時間＋姓名）。
6. **出圖**：按「產生計價圖」→ 前端 html-to-image 出兩張（§5）→ 上傳公開圖庫（同 sendMedia 路徑）→ 存進訂單 `imgs`。
7. **傳客人**：按「傳給客人」→ 兩張圖＋文字（總額／取餐時間／統編）走收件匣 sendMedia；客人頁面也直接看得到圖。
8. **雙方確認**：客人按「確認無誤」→ `confirmed`（記時間）；店家按「鎖單」→ `locked`，之後改動要先解鎖（留痕）。
9. **付款**：欄位 `pay`={status: 未付／訂金／已付, amount, method: 現場／轉帳／LINE Pay, paidAt}。第一批只手動改；第三批接金流回呼改這欄。
10. **完成**：取餐後店家標 `done`；紀錄頁可查歷史、同客戶再下單可「複製上次」。

## 4. 計價規則（跟 10/12 那兩張表同口徑）
- 每列總額＝主餐價＋套餐價（setN，現 89）＋補差價＋單點價。
- 套餐內：小點折抵 `sections[小點].combo`（60）、飲品折抵 `sections[飲品].combo`（50）；選的品項比折抵貴→補差價（番茄蔬菜湯 60−50＝10、冰美式 75−50＝25）；比折抵便宜不退。
- 不選套餐→小點／飲品全算單點價。
- 共用品項（披薩）不分攤到人，單獨列，總額另加。
- **只認最新菜單**（張良 10/12：客人剛好拿到上週舊菜單，是個案）：客人貼的文字對不到最新菜單的品項（例：川味微辣炸雞腿堡、費洛蒙起司薯條、松露蕈菇炸雞腿堡）→ AI 解析時標「待確認」並給最接近的最新品項讓客人或店家點選改，不提供手填價格。
- 飲品升級補差價照菜單標示（國寶鮮奶茶 +15、美式 +25、拿鐵 +40、番茄蔬菜湯 +10）＝品項價−折抵，來源同一份菜單資料，不另設表。
- 已鎖單的訂單把當時價格快照存進單內（`priceAt`），之後菜單改價不影響舊單；未鎖單一律即時跟最新菜單。
- 折扣：% 或金額，套總額；訂金只記不扣。
- 同一個數字（每列總額、全單總額）前端客人頁、店家頁、兩張圖**共用一支算法**（`js/grporder-calc.js`），不各算各的。

## 5. 兩張圖（版型照 10/12 張良給的樣）
- **01 個人明細與 POS 計價表**：抬頭（品牌／客戶／日期時間／統編）、每列＝姓名／主餐／套餐小點／套餐飲品／額外單點／主餐價／套餐價／補差價／單點價／總金額、合計列、底部計價說明＋共用披薩＋全單總額。
- **02 餐點類別・品項整合表**：依分類彙整每品項數量／單價／小計／分配給誰、總額核對式、底部**搬運建議**（§6）。
- 出圖沿用菜單圖那套（html-to-image，字體 Noto／Lora，品牌紅 #ce1611）；兩張各一個 HTML 模板 `public/ops/grporder-img.html?id=…&p=1|2`，存版本（同菜單圖 verSave 概念，留歷史）。

## 6. 搬運建議（客人真的會問）
cfg 預設：主餐＋薯條一份＝1 袋位；每袋 4 袋位；披薩 1 盒＝獨立一疊最多 3 盒；飲品 4 杯一提袋；一人可拿 2 袋＋1 疊披薩或 2 提袋。→ 算出「建議 N 人下來搬」，印在 02 圖底部，店家可在設定改規則。

## 8. 權限
- 客人頁：只認連結碼；一單一碼；到期（cfg，預設 14 天）或 locked 後唯讀。
- 店家頁：走 permWho＋EDIT_FN 新 fn `grporder`；改價／鎖單／改付款＝主管或被授權者；看＝正職以上。
- 個資（電話、統編）不進 DD 給未綁定者（沿用 secretOK 守門）。

## 9. 金流（第三批）— v4.71.1 程式已做（LINE Pay，沙盒先測；2026-10-12）
- 選擇：**LINE Pay**（規格建議首選；張良未另指定，先做這家，綠界之後要加再說）。
- 程式：共用模組 `api/_linepay.js`（request／confirm、HMAC 簽章、沙盒／正式切換）；`api/_grporder.js` `custPayReq`（客人頁 op=payreq）＋ `payConfirm`（導回 `?gorder=<碼>&payok=1`）；`publicView.pay`＝{status, method, amount, due, enabled, env}。
- 流程：客人確認金額（confirmed）或店家鎖單（locked）後 → **只有主辦人**在客人頁看到「LINE Pay 付款 $應付」→ 整頁導去 LINE Pay → 付完導回點餐單頁顯示「付款完成」→ 後端確認扣款、`pay` 改成 已付清／已付訂金＋method=LINE Pay＋paidAt＋txId，寫 edits，店家收鈴鐺＋LINE 通知；GD 團訂分頁側欄顯示「已收款 金額・LINE Pay・時間」。
- 應付金額＝鎖單快照總額（沒鎖＝即時總額）− 已收金額；付清後按鈕消失；模擬單不開付款。
- 安全：建立付款時把 transactionId 存 `pay.tx`，導回時 id 要對得上才確認；導回頁重新整理不會重扣（已確認過直接回成功）；金流只改 `pay`，不碰餐點內容。
- **張良前置（沒設就整個付款功能不出現，其他流程照舊）**：到 LINE Pay 商家後台（沙盒：pay.line.me/tw/developers/techsupport/sandbox/creation 申請測試商家）拿 Channel ID／Channel Secret → Vercel env `LINEPAY_CHANNEL_ID`、`LINEPAY_CHANNEL_SECRET`；正式上線再加 `LINEPAY_ENV=prod`（沒設＝沙盒，客人頁會標「沙盒測試」）。
