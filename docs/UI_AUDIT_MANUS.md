# GROUND:D 工程專案管理系統 — 介面優化方向建議報告

**分析對象**：[https://ground-pm.vercel.app/](https://ground-pm.vercel.app/)
**分析方式**：實際操作網站全部九個主要頁面（儀表板、總覽、任務、工序、結論、檔案庫、零用金、比價、AI 顧問），並比對企業級 SaaS 與專案管理軟體的設計最佳實踐
**撰寫**：Manus AI · 2026 年 7 月

---

## 一、整體評價

先說結論：這個產品的**功能深度遠超過一般自建工具的水準**。財務三層結構（預估／已付／未付）、零用金獨立帳本併入工種成本、工序時間格網搭配施工照片紀錄、AI 解析估價單與自動歸類、LINE bot 整合——這些是很多商用工程管理軟體都做不到的完整度。

目前介面的核心問題不在「不好看」，而在於**功能長得比介面架構快**：每個功能都直接堆在頁面上，缺乏「檢視」與「編輯」的分離、缺乏資訊層級的收斂，導致專業的功能被雜亂的視覺稀釋了。以下按影響程度排序，給出六大優化方向。

---

## 二、六大優化方向（按優先級排序）

### 方向 1：表格「檢視／編輯」分離 — 影響最大的一項改動

這是整個系統最值得優先處理的問題。目前「總覽」與「零用金」頁的做法是：**每一列的每個欄位都永遠渲染成可編輯的 input／select**。實測「零用金」頁 168 筆明細，每列都掛著日期選擇器、含 40 多個選項的工種下拉、金額輸入框、憑證下拉與多個 checkbox；「總覽」頁更是每列都有改名、議價輸入、清空細項、刪除等操作直接外露。

這造成三個具體傷害：

| 問題 | 說明 |
| --- | --- |
| 閱讀效率低 | 使用者 90% 的時間是在「看數字、比對數字」，但滿版的輸入框邊框與下拉箭頭讓眼睛無法快速掃描 |
| 效能負擔 | 數百個表單控制項同時渲染，頁面初次載入已出現「太久沒反應？點此重新整理」的狀況 |
| 誤觸風險 | 「清空細項」「刪除大項 ×」這類破壞性操作與一般欄位並排，沒有視覺區隔，手一滑就可能出事 |

**建議做法**：表格預設為純文字的唯讀狀態（數字右對齊、等寬字體），提供兩種編輯入口擇一或並用：

1. **列內編輯（Inline Edit）**：點擊該列或列尾的鉛筆圖示，該列才切換為可編輯狀態，按 Enter 儲存、Esc 取消。適合快速改單一欄位。
2. **側邊抽屜（Drawer）**：點擊細項名稱，從右側滑出詳情面板，集中呈現該筆的所有欄位、付款紀錄、憑證縮圖與備註。適合欄位多的完整編輯，也順便解決了目前 15 欄橫向捲動的問題——表格只留 6~7 個關鍵欄（名稱、狀態、預估、已付、未付、負責人），其餘進抽屜。

破壞性操作（刪除、清空）收進列尾的「⋯」更多選單，並加二次確認，用紅色標示。

### 方向 2：建立設計系統 — 用專業圖示取代 Emoji、統一按鈕與色彩

目前全站以 Emoji 充當圖示（🏗👥🤝💰📌⚙🔥🥇🪙🤖…），且導覽列命名不一致（「✅ 任務」「📌 結論」帶符號，「工序」「檔案庫」不帶）。Emoji 在 Windows、Android、iOS 上的長相各異，也讓整體氣質偏向「個人工具」而非「可以拿給業主看的系統」。

**建議做法**：

1. **導入 SVG 圖示庫**：Lucide、Phosphor 或 Heroicons 任選一套，全站統一線條粗細與尺寸。導覽列九個分頁全部「圖示 + 文字」一致呈現。
2. **收斂按鈕階層**：目前藍色按鈕（AI 顧問、新增）、黑色按鈕（登入、產生週報、AI 比價分析）、白底按鈕並存且無規則。建議定義四級——Primary（每頁最多一顆）、Secondary、Ghost/文字按鈕、Danger——並全站套用。
3. **固定色彩語意**：綠＝已付/完成、橘＝進行中/部分付款、紅＝逾期/警示/刪除、灰＝待開工/停用。目前大致有此邏輯，但要修正矛盾案例，例如儀表板出現「工程雜支 122/122・100%・**待開工**」——進度與狀態互相打架，會讓人不信任數據。建議狀態由進度自動推導，或至少在衝突時顯示提醒。
4. **金額一律等寬字體（tabular-nums）+ 右對齊**：這是財務密集介面最基本也最見效的排版原則，方便上下比對位數。

### 方向 3：儀表板資訊分層 — 區分「業主視角」與「管理視角」

儀表板目前一頁塞了七大塊：警示條、財務總覽、四張指標卡、29 項工程進度全列表、今日動態 17 筆、卡關清單，最後還有「D哥 LINE bot API 花費」與「AI 用量估算」兩張開發者帳單卡。頁面往下捲近三個螢幕高。

**建議做法**：

1. **AI/bot 用量帳單移出儀表板**，放到「⚙ 設定」內的「系統與用量」分頁。業主點開「產生業主週報」的系統，首頁卻看得到 Anthropic API 帳單，資訊層級明顯錯位。
2. **工程進度列表預設收斂**：29 項全列太長。預設只展開「進行中 + 有異常」的項目，完工的收進摺疊區塊（「已完工 12 項 ▸」），或提供狀態分頁籤。
3. **今日動態改為可捲動的固定高度區塊**或只顯示前 5 筆 +「查看全部」，把垂直空間還給更重要的卡關與財務資訊。
4. **考慮兩欄式佈局**：左欄放財務與進度（主資訊流），右欄放動態、卡關、待辦（輔助資訊流），減少縱向捲動距離。

### 方向 4：行動裝置體驗 — 工地場景的關鍵

工程管理的實際使用情境有一大半發生在工地現場的手機上（你們也已經做了 LINE bot 整合，證明行動場景很重要）。但目前的主戰場頁面都是超寬表格與超寬時間格網，在手機上幾乎必然需要雙向捲動。

**建議做法**：

1. **表格在窄螢幕自動轉卡片**：每筆細項變成一張卡片，第一行放名稱與狀態章，第二行放預估/已付/未付三個金額，點卡片進抽屜看全部欄位。
2. **工序時間格網在手機改為「單日／三日檢視」**，上方橫向滑動選日期，下方縱向列出當日各工種的紀錄。
3. **觸控目標至少 44×44px**：目前列尾的「×」「✎」「⠿」等小按鈕在手機上很難點準。
4. **底部導覽列**：手機版把最常用的四個分頁（儀表板、任務、工序、零用金）放到底部 tab bar，符合單手操作習慣。

### 方向 5：長列表效能與載入體驗

實測首次載入會停在「載入中…太久沒反應？點此重新整理」一段時間；零用金頁面總高度近 8,000px。這與方向 1 的全量渲染直接相關。

**建議做法**：

1. **虛擬滾動或分頁**：零用金 168 筆、未來只會更多，建議引入虛擬清單（如 `@tanstack/react-virtual`）或每頁 50 筆的分頁。
2. **Skeleton 載入畫面**：以灰色骨架取代「載入中…」文字，感知速度會快很多；並考慮把首屏需要的資料與次要資料（活動紀錄、AI 用量）分批載入。
3. **共用的工種選單資料**：40 多個工種選項目前在每一列的 select 都完整複製一份，改為單一資料來源 + 搜尋式下拉（combobox），既省記憶體也更好選。

### 方向 6：文案與細節打磨

目前介面文案偏口語且偏長，例如任務輸入框的 placeholder「隨手丟一句任務…（先進收件匣，之後再拖到大項整理）按 Enter 新增」、工序頁表頭的操作說明「點格子＝記錄 · 橫向拖曳空格＝設工期 · 拖紀錄到別格＝改日期/工序」。口語化是這個產品的個性，可以保留，但建議：

1. **說明性文字移到 tooltip 或首次使用的引導提示（onboarding hint）**，placeholder 保持簡短（「輸入任務，Enter 新增」），介面才呼吸得起來。
2. **檔案庫的檔名截斷與去重**：超長檔名（「B4659.115.5.30.喬亞國際餐飲股份有限公司…」）應中間截斷顯示，同一份 PDF 重複上傳三次也應偵測提示；「未指定工程」的檔案占多數，可在上傳時（尤其 LINE bot 匯入時）強制或 AI 建議歸類。
3. **空狀態設計**：結論頁只有 1 條資料時大面積留白，可放插圖 + 「新增第一條結論」的引導按鈕；任務中心下半部的空白同理。
4. **未登入的唯讀狀態要一致**：目前檔案庫有「🔒 唯讀模式」提示，但總覽/零用金頁未登入時所有編輯控件照常渲染。建議未登入一律以唯讀呈現（也順便解決訪客能看到全部真實財務數字的隱私問題——可考慮訪客模式數字打碼或需連結權杖才能存取）。

## 三、優先級與預期效益總表

| 優先級 | 優化項目 | 工作量 | 預期效益 |
| --- | --- | --- | --- |
| P0 | 表格檢視/編輯分離 + 破壞性操作收斂 | 中 | 閱讀效率與安全性大幅提升，效能連帶改善 |
| P0 | SVG 圖示取代 Emoji + 按鈕/色彩規範 | 小 | 專業感立即提升，成本最低見效最快 |
| P1 | 儀表板資訊分層（移出 AI 帳單、收斂進度列表） | 小 | 業主/管理視角清晰，首頁變短變聚焦 |
| P1 | 長列表虛擬滾動 + Skeleton 載入 | 中 | 首次載入體感速度與大量資料流暢度 |
| P2 | 手機版卡片式佈局 + 底部導覽 | 大 | 覆蓋工地現場最重要的使用情境 |
| P2 | 文案精簡、空狀態、檔案庫細節 | 小 | 整體質感打磨 |

## 四、建議的執行路徑

第一週可以先做「零成本高回報」的三件事：全站替換圖示庫並統一按鈕樣式、金額改等寬字體右對齊、把 AI 用量卡移到設定頁。這三項不動任何資料邏輯，純前端樣式調整，但介面觀感會有立即可見的躍升。

第二階段（約 1–2 週）處理總覽與零用金的表格重構：唯讀預設 + 側邊抽屜編輯 + 虛擬滾動，這是整個系統體驗的分水嶺。第三階段再投入手機版佈局，讓 LINE bot 回報與現場查看形成完整的行動閉環。
