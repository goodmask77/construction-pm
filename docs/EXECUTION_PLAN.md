## DD 穩定化(項目 3 的規格)

已知問題(先用 log 驗證再修):

1. **整包塞資料**:`answer()` 每次把十幾類資料(`snapshotsToContext` 等)全部塞進 system prompt → 慢、被截斷(`slice(-30)`、「中段略」)、貴。改成工具查詢:DD 先判斷問題類型,再呼叫對應查詢工具(成本、決策、訂位、班表、任務、財務……),只取需要的資料;每個工具回傳時標資料時間
2. **回覆逾時無補救**:`lineReply` 失敗只記 log,使用者看到沒反應。改成收到訊息先秒回「收到,查詢中…」,答案以 push 送達;push 失敗重試並記錄
3. **對話記憶互相覆蓋**:所有對話存在同一 KV 鍵 `pm_bot_chats`,讀改寫會被並發覆蓋。改成每個對話各自一筆;滾動摘要同樣分開存
4. **DD 健康頁**:最近 7 天回應時間分佈、失敗次數與原因、被截斷次數、走備援模型次數

完成條件:測試群連續問 30 題(含同時兩人發問)無遺失、無無回應;健康頁數字正確。
