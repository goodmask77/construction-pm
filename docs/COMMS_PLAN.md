## 第一部|執行計畫

### 核心規則(摘要,細節見規格)

1. **一顆大腦兩個入口**:DD 與 app AI 助理共用快問引擎、查詢工具、資料邊界
2. **權限跟著提問者**,不跟著群組;個人事項(薪資、分潤、請假原因、健康、家庭、申訴)自動標私人,只有本人與張良可見
3. **AI 一律讀不到**:入職機密檔、身分證號、銀行帳號、健檢、個人薪資分潤、個人考評
4. **AI 只預填,人確認**:AI 抓出的決議、回覆建議、對話分類,都要人確認才生效
5. **每個對話各自一筆紀錄**,不可多個對話擠在同一個 KV 鍵
6. **回覆統一從 app/DD 發**;官方帳號後台不再手動回覆
7. 所有 AI 呼叫走 `api/_ai.js` AI 中樞,費用記進用量儀表板

### DD 穩定化(項目 1 的規格)

先用 log 驗證以下問題,依實際失敗原因排序修:

1. **整包塞資料**:`answer()` 每次把十幾類資料(`snapshotsToContext` 等)全部塞進 system prompt → 慢、被截斷(`slice(-30)`、「中段略」)、貴。改成工具查詢:DD 先判斷問題類型,再呼叫對應查詢工具,只取需要的資料;工具回傳標資料時間。這批做的查詢工具就是項目 4 快問引擎要用的工具,寫成共用模組
2. **回覆逾時無補救**:`lineReply` 失敗只記 log,使用者看到沒反應。改成先秒回「收到,查詢中…」,答案以 push 送達;push 失敗重試並記錄
3. **對話記憶互相覆蓋**:所有對話存在同一 KV 鍵 `pm_bot_chats`,並發時讀改寫會覆蓋。改成每個對話各自一筆;滾動摘要同樣分開存
4. **DD 健康頁**:最近 7 天回應時間分佈、失敗次數與原因、被截斷次數、走備援模型次數

## 第二部|AI 助理與會議室規格

在 app 裡讓 Claude、ChatGPT、Gemini 照固定規則一起討論,手機隨時可開;每場會議自動產出紀錄與決策,存進決策帳本,之後 AI 與 DD 都查得到。建在既有 AI 中樞(`api/_ai.js`)上,不另接 API。

### 決策

| # | 主題 | 決策 |
| --- | --- | --- |
| 1 | 位置 | app 內新增「AI 會議室」;手機版為主要使用情境 |
| 2 | 兩種模式 | **快問**:單一 AI、依公司文件回答,給所有夥伴與 DD 用;**會議**:三家照流程討論,產出決策 |
| 3 | 記憶 | 記「決策」不記「對話全文」:每場會議寫入決策帳本;新會議自動帶入相關的過去決策 |
| 4 | 共識 | 不用多數決;一律輸出「共識」與「分歧」兩部分,分歧由人裁決 |
| 5 | 殭屍條款 | 已裁決的決策要重開,必須附上新事實,否則系統擋下並顯示原決策 |
| 6 | 權限 | 預設全員可看會議紀錄與決策;個資類資料 AI 一律讀不到(見「資料邊界」) |
| 7 | 不碰程式 | 會議室的 AI 只產出文字;要改程式的結論轉成 CC 任務,照 PR 流程 |
| 8 | 真人會議 | 錄音轉逐字稿、摘要、待辦;決議經主持人確認才進同一本帳本 |

### 會議流程(後端強制,不靠提示詞自律)

1. **開會**:發起人填題目、背景、要決定的事;可附檔案或照片;系統自動帶入相關的過去決策(依標籤與關鍵字比對,上限 5 筆)
2. **獨立作答**(同時送三家,互相看不到):每家回答立場、理由、證據、風險;限 400 字
3. **互相詰問**(最多 2 輪):每家看到另外兩家的答案,只能回覆「同意哪幾點」「反對哪幾點與理由」「對方漏掉什麼」;不得重複自己第一輪的內容
4. **融合**:由一家當整理者(預設輪流,設定頁可改),產出:共識清單、分歧清單(每條附各家立場原文摘要,不可改寫成整理者自己的意見)、建議決定
5. **人裁決**:發起人逐條處理分歧——選一家的、自己寫、或標「待事實」(註明缺什麼資料)
6. **行動建議與紀錄**:產出行動清單(做什麼、誰、期限)、三行重點摘要、完整會議紀錄;決策寫入帳本

任何一步都可以由發起人補充事實,補充內容會帶進下一步。整場最多約 9–12 次 AI 呼叫,開會前顯示預估費用(用 AI 中樞的用量與單價表)。

### 快問模式

- 單一 AI(預設 Claude,走 AI 中樞路由 `council_ask`),回答時只能根據:決策帳本、公司文件(`docs/` 規格、SOP、GOS 手冊)、app 內可公開的營運數字
- 回答要附來源(哪一筆決策或哪份文件);找不到依據就說「沒有相關資料」,不可自己推測公司規定
- 可一鍵「升級成會議」

### DD 串接(LINE 為主要入口)

DD 與 AI 會議室共用同一個後台與決策帳本;LINE 是夥伴最常用的入口,app 是完整版。

| 功能 | LINE 上的做法 |
| --- | --- |
| 快問 | 直接問 DD,DD 走 `council_ask` 回答並附來源;找不到依據就說沒有相關資料 |
| 查決策/查會議 | 「上次 X 怎麼決定」→ 回決策內容與 app 連結 |
| 開會 | 「開會:題目」→ DD 在背景跑會議流程 → 回傳摘要 Flex 卡片:共識、分歧(每條附按鈕選哪一家或「我自己寫」)、行動清單、完整紀錄連結;裁決按鈕直接寫回帳本 |
| 會議錄音 | 私訊 DD 傳錄音檔 → 轉逐字稿與摘要 → 回傳決議候選 Flex 卡片供主持人勾選確認;長錄音建議用 app 上傳 |

**權限跟著提問者,不跟著群組**

- DD 先由 LINE 綁定辨識提問者,依其 app 權限決定能回答到哪裡
- 群組裡被問到人事類會議、或提問者無權限的內容 → 只回「請私訊查詢」,不在群組顯示內容
- 未綁定的 LINE 使用者只能用快問,且只回答公開文件範圍
- 開會、裁決、確認決議只限有權限者;群組中他人按裁決按鈕無效並提示
- 費用:LINE 發起的會議同樣先回覆預估費用,確認後才開始

### 資料邊界(AI 一律讀不到)

- 入職機密檔、身分證號、銀行帳號、健檢報告(私有桶 `ground-private` 全部排除)
- 個人薪資、分潤明細、個人考評
- 員工私訊內容
- 需要時可在設定頁開「管理者專用會議」,仍不開放上述資料給 AI

### 真人會議錄音(批次 D)

真人開會時用手機錄音,會後自動產出逐字稿、重點摘要、待辦,決議經主持人確認後寫入同一本決策帳本。

**流程**

1. 開會前在 app 建立會議:題目、與會者(從名冊選)、類型(一般/人事);按「開始錄音」時畫面提醒主持人告知與會者正在錄音
2. 手機錄音,可暫停;結束後自動分段上傳(避免大檔失敗),錄音存私有桶
3. 轉逐字稿:走 AI 中樞路由 `meeting_transcribe`(Claude 不支援音檔,預設用 OpenAI 或 Gemini 的語音轉文字,設定頁可換);中英台語混用照原樣轉
4. 發言人標示:依與會者名單由 AI 推估,標「估」;主持人可在逐字稿上改
5. 產出(走 `meeting_summary`,預設 Claude):三行重點、各議題摘要、**決議候選**、待辦(做什麼、誰、期限)、未決事項
6. 主持人確認:決議候選逐條勾選「是決議」或「不是」,確認的才進決策帳本;待辦可一鍵轉成任務並通知負責人(LINE)
7. 未決事項可一鍵「送 AI 會議室」,由三家照會議流程討論

**規則**

- AI 從對話抓出的決議只是候選,一律主持人確認才入帳(開會常說的「好像可以」「再看看」不是決議)
- 人事類會議:逐字稿與摘要預設只有主持人可看,決議可選擇公開
- 錄音檔保留 30 天後自動刪除(設定頁可調),逐字稿與紀錄永久保留
- 每場的轉檔與摘要費用記進 AI 用量儀表板;開錄前顯示每小時預估費用

**驗收**

- [ ] 60 分鐘錄音能完整上傳、轉出逐字稿(中途斷網可續傳)
- [ ] 發言人標「估」,主持人可修改
- [ ] 決議候選未經主持人確認不會進決策帳本
- [ ] 待辦轉任務後負責人收到通知
- [ ] 人事類會議其他人看不到逐字稿

### 已知限制(寫給所有人看)

1. **個人 LINE 帳號的聊天無法串接**。廠商對話要進 app,必須在有 DD 的群組裡進行;從 app 回覆時,訊息由 DD 發出,不是以個人名義
2. **回覆可能扣訊息額度**:收到訊息後短時間內用 reply 免費;超過時效只能 push,會計入該官方帳號的每月訊息則數。app 回覆框要顯示「這則免費/會扣額度」與本月剩餘
3. **回覆統一從 app 發**:官方帳號後台的手動聊天回覆不一定會進 webhook,混用會造成紀錄缺口;上線後規定一律從 app 回覆
4. **每個官方帳號只有一個 webhook 網址**:改設定前先確認目前是否已接其他系統(訂位、阿桑 OPS app 等);若已被佔用,改用轉發(收到後轉送給原系統)或與該系統協調

### 架構

- 單一接收端點 `api/inbox-webhook.js`,依 webhook 內容的 `destination`(官方帳號 ID)分辨是哪個帳號;各帳號的 channel secret / access token 放環境變數,每個請求都驗證簽章
- 廠商群組訊息由 `api/line-webhook.js`(DD)收到後,另寫一份進收件匣;不改動 DD 既有回答邏輯
- 每則訊息存一筆(帳號、對話、發送者、時間、類型、內容、附件路徑、方向 in/out、由誰從 app 送出);**每個對話各自一筆對話紀錄,不可全部擠在同一個 KV 鍵**(避免 DD 的覆蓋問題重演)
- 圖片、檔案下載後存私有桶,app 用短效網址顯示
- 客人個資(顯示名稱、電話、訊息內容)屬個資:收件匣依帳號設權限,預設 A Beach 客服只給 A Beach 指定人員、招募只給招募負責人

### 頁面

1. **收件匣列表**:上方帳號分頁(全部|A Beach 客服|GROUN:D 客服|招募|廠商),每列標帳號;每個對話一列(帳號標籤、對方名稱、最後一則、時間、未讀數、狀態、負責人);排序:未讀 > 待處理 > 時間
2. **對話頁**:時間軸顯示訊息(含圖片、貼圖、檔案);下方回覆框顯示「免費/扣額度」;常用回覆範本;指派給某人;狀態(新/處理中/已完成);內部備註(客人看不到)
3. **通知**:新訊息即時通知負責人(app 推播或 DD 私訊),超過設定時間未回覆再提醒
4. **設定**:帳號清單與連線狀態、權限、範本、自動提醒時間、額度顯示

### 內部對話(夥伴與 DD/AI 助理)

收件匣也顯示夥伴與 DD、app AI 助理的對話,讓管理者看到大家在問什麼、DD 答錯或答不出來時由真人接手回覆,作為公司未來的統一溝通管道。

- **公開範圍**:群組對話與工作問題預設對管理者可見;**私訊中涉及個人事項**(薪資、分潤、請假原因、健康、家庭、申訴)自動標為私人,只有本人與張良可見。分類由 AI 判斷、標「估」,本人可改為公開或私人
- **上線前公告**:讓所有夥伴知道「和 DD 的工作對話管理者看得到」,並說明哪些會自動私人
- **真人接手**:管理者在某個對話按「接手」後,DD 在該對話暫停自動回答(預設 30 分鐘或直到按「交還 DD」),避免 DD 和真人同時回覆;真人回覆以 DD 名義送出並標「(某某回覆)」
- **DD 答不出來**:DD 回「沒有相關資料」或使用者按「這不是我要的」時,該對話自動進收件匣「待真人」並通知管理者
- 每個對話各自一筆紀錄(與 DD 穩定化的改法一致)

- 精確規則以批次 0 查到的 Meta 官方文件為準

### 開發流程(張良 2026-10-10 定)

1. 一次只做一項;**改到程式一律開 PR,不直接推 main**;PR 附 Vercel 預覽網址,張良回「merge」才合併

### 多 AI 協作規則(CC 開發時,OpenAI、Gemini 經 API 參與審查)
