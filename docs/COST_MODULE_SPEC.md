# 產品與成本模組|整合規格 v2

營運 app 新增「產品與成本」模組:把叫貨、物料、食譜、菜單、包材串成一條可追溯的成本鏈,並以「偵錯與待處理中心」把價格錯誤和單位錯誤攔在源頭。本版整合 2026-10-06 成本總表分析、GPT 開工規格 v1 與 10/10 的十點裁決;ops 搬家另案,不在本文件。

以下為已拍板事項,開發以此為準;與 GPT 規格 v1 衝突處以本表為準。

## 頁面架構

```text
驗收(既有頁) ──單價寫入價格紀錄──┐
                                  ▼
廠商與月帳 ──供應品──▶ 物料庫＋物料卡 ──單位成本──▶ 食譜庫 ──食譜成本──▶ 菜單與定價
                         │      ▲                     │                     │
                     偵測異常  結論回寫             缺口上傳            成本與毛利
                         ▼      │                     ▼                     ▼
                  ┌───────────── 偵錯與待處理中心 ─────────────┐ ──▶  成本總覽(首頁)
                  │ 價格異常・單位待確認・資料缺口・合併建議・已靜音 │
                  └──────────────────────────────────────────────┘
權限設定:每頁看/改權限開關,預設全部公開(橫跨所有頁面)
```

主線由左到右:廠商與驗收把價格寫進物料卡,物料卡算出單位成本給食譜,食譜成本再進菜單;任何一環發現異常都進待處理中心,人確認後的結論回寫物料卡,成本自動重算並留版本。

## 各頁面規格

模組共七個頁面,上方統一有品牌/門店切換與搜尋;另有一個既有頁面(驗收)要加攔截。停用品項預設隱藏,篩選可顯示。

### 1. 成本總覽(首頁)

一眼看到「哪裡有問題、影響多大」。

- 上區四格數字:在賣餐點成本完整數/總數、待處理件數(點進待處理中心)、成本率超標數、本週變價數
- 下區兩塊:「本週成本變動」(依每份增加金額排序,列出是哪個物料造成)、「待處理前 10 筆」
- 成本率上限由管理者依品類設定;未設定顯示「未設定」,不套預設值
- 每個數字標明資料更新時間;成本不完整的品項不計入平均毛利

### 2. 偵錯與待處理中心(新)

所有「需要人決定」的事集中在這裡;偵測規則見第 4 節。五個分頁:

| 分頁 | 放什麼 | 可以做的決定 |
| --- | --- | --- |
| 價格變動紀錄 | 每一筆驗收價與系統紀錄價不同的紀錄(含門檻內的小變動),顯示舊價→新價、差額 %、廠商、驗收人、日期、每份成本影響 | 確認(單筆或勾選批次確認) / 標為打錯並更正 / 是單位問題(轉到單位待確認) |
| 價格異常 | 超過門檻的變價、歷史序列偵測到的尖峰 | 確認正確 / 更正金額 / 是單位問題(轉到單位待確認) / 不再顯示 |
| 單位待確認 | 一碼多單位、整數倍跳動、g/ml 1:1 假設、缺換算、規格文字與換算不符 | 接受建議換算 / 手動輸入 / 拆料號 / 不需換算(填原因) |
| 資料缺口 | 缺價、缺料號、停用品仍被食譜引用、食譜行沒對到物料、白名單外的不計成本 | 補資料 / 指定替代料 / 標不計成本(填原因) |
| 合併建議 | 同名或近似名的多代碼(目前 A Beach 111 組、GROUN:D 8 組) | 合併進同一張物料卡 / 不是同一物(不再建議) |
| 已靜音 | 所有被選「不再顯示」的項目、誰選的、何時、範圍 | 取消靜音 |

- 每筆待處理顯示:物料、問題、系統判讀與依據(例:「140→12→120,疑似少打一個 0」)、影響幾道在賣菜、每份影響金額、發生日期
- 排序:影響在賣菜單的優先,再依每份影響金額
- 選任何決定都要留紀錄(誰、何時、選了什麼、原因);更正金額走 order_adjust 並可附送貨單照片
- 導覽列顯示未處理件數徽章

### 3. 物料庫 ＋ 物料卡

列表欄位:照片、料號、品名、類型(原料/半成品/包材/非食品)、分類、主要廠商、成本基準價(每基準單位)、完整狀態。篩選:品牌、類型、分類、存放、廠商、狀態、缺換算、缺價。搜尋含品名、料號、所有舊代碼。類型「包材」提供照片牆檢視。

物料卡五個分頁:

1. **基本資料**:內部 ID(不變)、顯示料號、品名、類型、基準單位(g/ml/個)、存放、工作站、照片、適用品牌、狀態
2. **供應品與價格**:合併進來的每個舊代碼各一列(廠商、規格、叫貨單位、現價、每基準單位價、稅別、最後叫貨日);標一個「主要來源」作為成本基準;下方價格走勢圖(各代碼一條線,換算成每基準單位才可比);可輸入日期查「當時價」
3. **單位換算**:所有換算列表＋自動計算結果(例:1 箱 = 6 包 = 6,000 g → 0.053 元/g);規格文字(如「1000g/罐」)自動解析成建議換算,待人確認
4. **被使用於**:直接與經半成品間接使用的食譜、菜單,點擊可進
5. **紀錄**:變價、改換算、合併/拆分、靜音的完整歷程

### 4. 食譜庫 ＋ 食譜詳情 ＋ 製作模式

- 列表:照片為主,顯示工作站、半成品/餐點、版本、產量、每單位成本、完整狀態
- 詳情分頁:材料、步驟、成本、版本紀錄
- 材料每行顯示完整換算鏈(叫貨價 → 換算 → 單位成本 × 用量 = 行成本);半成品可展開成樹狀;行成本由系統算,不可手填
- 步驟每列:順序、標題、說明、相關材料、照片/影片、計時秒數,可拖曳排序
- 版本:新增為草稿,發布後不可直接覆寫,修改產生新草稿;發布前檢查材料可解析、產量 > 0、無循環引用
- 成本分頁:成本走勢圖＋每次變動的差異標記(例:「10/03 +12.6 元:綠櫂瓜 100→200」)
- 製作模式:桌面左材料右步驟,切步驟同步標示該步材料;手機上步驟、材料抽屜、底部上一步/下一步/計時;份量倍率只影響當次顯示不改食譜;計時切頁後恢復倒數

**A Beach 現有食譜直接上線**:ops 已有 195 份備料食譜(啟用 190)與 90 道在賣菜的出餐食譜,食譜庫直接讀這些資料,不重新輸入。現有資料只有材料、用量、成品量,**沒有步驟、照片、影片**,這部分是要補的內容。

| 類型 | 來源 | 數量 | 要補的 |
| --- | --- | --- | --- |
| 備料食譜(半成品) | ops.recipes | 195 份,啟用 190,成本不完整 36 | 步驟、照片/影片、保存說明、實測產量 |
| 出餐食譜(組裝) | ops.menu_items 的食譜行 | 在賣 90 道(停售 27 不抓) | 打盤步驟、成品照、出餐時間 |

食譜庫用兩個篩選切開:「備料」(依工作站 Pizza/內場/吧台)與「出餐」(依菜單品類)。每份顯示「內容完整度」:材料 ✓ / 步驟 ✗ / 照片 ✗,讓補內容的進度看得到。補步驟是內容工作不是工程,建議依工作站指定負責人,先補在賣菜用到的備料。

### 5. 菜單與定價

- 列表:品名、品類、規格、通路、售價、食材成本、包材成本、成本率、毛利率、完整狀態、在賣/停售
- 規格分開:同一品項可有多規格(4oz/8oz、M/L),各自售價與用量,不可整份加倍
- **包材欄位**(GROUN:D 先做):依內用/外帶/外送各設一組包材,從物料庫選類型「包材」的物料卡,帶照片縮圖與數量;包材成本自動連動該物料卡的廠商價格
- 套餐:主餐＋可選附餐＋可選飲料＋額外包材與加價;顯示每種合法組合的成本與最低/最高範圍;同一份包材不重複計入;加價金額是設定值不寫死
- 試算:改售價、份量、模擬原料價,不寫正式資料;按「建立新版本」才進發布
- 每道菜的成本歷史與差異標記,同食譜

### 6. 廠商與月帳

- 列表:名稱、狀態、稅別、結帳區間、供應品數、最後採購日、本月系統金額
- 詳情:供應品、報價歷史、採購單、月帳對帳入口(連回既有頁,不另建帳款系統)
- 對帳修正:廠商帳單金額改為「未稅、稅額」兩格填,系統自動加總比對,消除未稅廠商恒差 5% 的假差額;帳單金額為負或與系統差 > 50% 時提醒再確認
- GROUN:D 補上 vendor_recon 月帳功能,與 A Beach 同口徑

### 7. 權限設定

- 預設:所有人看得到所有數字
- 權限表以「功能 × 角色」開關呈現:看成本、看售價試算、改價格/換算、改配方草稿、發布、處理待處理、靜音
- 關掉的權限在 API 層就不回傳,不只是畫面隱藏;沿用既有登入與角色

### 既有頁修改:驗收攔截

驗收價和系統紀錄價(該供應品最近一次已確認的驗收進價)不同時,分兩級:

- **門檻內**:畫面跳提示「價格與上次不同:舊價 → 新價」,可直接送出;這筆寫入「價格變動紀錄」狀態為待確認,新價**立即**成為成本依據,之後在紀錄頁確認
- **超過門檻**:跳確認框,顯示近期價格點與差距,驗收人必須選原因(真的漲跌價 / 這次單位不同 / 打錯了我改)才能送出,可拍送貨單;同樣寫入價格變動紀錄,但新價**在管理者確認前不進成本**,成本仍用上一個已確認價並標「待重算」
- 「打錯了我改」:驗收人當場改正,原輸入值與改正值都留紀錄

## 偵錯規則與處理流程

偵測只負責「標記＋建議」,不自動改任何金額或換算;最後拍板以送貨單或廠商帳單為準。

### 三個觸發點

1. **驗收當下**:單價與系統紀錄價不同即提示並寫入價格變動紀錄;與最近 3 張單的中位數差超過門檻則攔截(見「既有頁修改:驗收攔截」)
2. **每日排程**(歷史掃描):對整個價格序列跑形狀判讀,補抓漏網的
3. **資料變更時**:改現價、改換算、停用物料時,檢查是否產生新的缺口或異常

### 判讀訊號

| 訊號 | 判斷方式 | 指向 |
| --- | --- | --- |
| 形狀 | 單點跳起後回原價(A→B→A) | 打錯或單位混用 |
| 形狀 | 階梯式、沒回來 | 真的變價 |
| 交替 | 兩個價格來回跳(750↔105) | 一碼多單位 → 單位待確認 |
| 倍率 | 整數倍(×2、×10、×6)或等於規格換算 | 單位混用 |
| 倍率 | 剛好少/多一位數(140→12) | 打錯字 |
| 金額守恆 | 單價 ×N 且數量 ÷N,整行金額不變 | 單位混用,付的錢沒錯 |
| 跨廠商 | 同物料卡的其他廠商同期也變(換算成每基準單位比) | 真的變價,降級為資訊 |
| 開帳週 | 首價落在系統上線首週,之後沒再出現 | 開帳初始價錯誤,從統計排除 |
| 月帳 | 該廠商當月對帳差額為 0 | 金額已被帳單驗證 |

**門檻依品類設定**(管理者可改):蔬果類波動大,門檻放寬(建議 ±80%);起司、乾貨、包材、耗材收緊(建議 ±30%);其他 ±50%。上線後看誤報率再調。

### 單位偵測的來源

- 同一代碼價格交替或整數倍跳動
- 換算中同時有 g 與 ml 且數值相同(1:1 假設)
- 庫存單位非公制、又沒登記換算
- 規格文字解析出的量與登記換算不符(例:規格「1000g/包」但換算寫 g=500)
- 食譜用量單位在該物料找不到換算

### 處理流程

1. **排除與確認**(必要):待處理頁顯示系統判讀與依據,處理人選結論——確認正確 / 更正金額(走 order_adjust,附送貨單) / 修正換算 / 拆料號 / 排除這筆不進價格統計。任何結論都留紀錄
2. **不再顯示**(可選),分三種範圍:
   - 「這一筆已確認」:只關這次;之後若再偏離新基準仍會提醒(預設)
   - 「N 天內不提醒」:適合颱風季蔬菜
   - 「此物料停用這條規則」:永久靜音,需填原因,列在「已靜音」可隨時還原

不提供「整個物料永久不提醒任何事」:一個物料的真體重問題未來會被蓋掉。

- 驗收攔截:當場彈窗
- 選配:每日摘要推到 LINE(待處理件數＋影響最大的 3 筆),不逐筆推,避免通知疲勞

## 資料模型

核心是「物料卡」與「供應品」分開:食譜綁物料卡,叫貨綁供應品(就是現在的舊代碼),價格永遠只新增不覆寫。下表是邏輯模型,實際表名由 CC 核對現有 schema 後決定。

| 實體 | 內容 | 關係 |
| --- | --- | --- |
| 物料卡 | 不變內部 ID、顯示料號、品名、類型(原料/半成品/包材/非食品)、基準單位、照片、適用品牌、主要供應品、狀態 | 一張卡對多個供應品 |
| 供應品(舊代碼) | 來源 schema、舊代碼、廠商、規格、叫貨單位、包裝量、稅別、所屬物料卡 | 舊代碼永遠保留,統一料號後變別名 |
| 價格紀錄 | 供應品、價格、稅別、生效日、來源(驗收/報價/手動)、來源單據、原因、是否排除統計 | 只新增不覆寫;查「當時價」= 該日前最後一筆 |
| 合併/拆分紀錄 | 哪些供應品併進哪張卡、誰、何時、原因;拆分時歷史叫貨行的歸屬規則 | 可還原 |
| 單位換算 | 物料卡或供應品、來源單位、目標單位、倍率、狀態(已確認/建議中)、版本 | 倍率必為正值 |
| 不計成本白名單 | 水、生飲水、純淨水、熱水、溫水、冰塊、碎冰 | 系統常數,管理者可增減 |
| 食譜版本 | 食譜 ID、版本、類型(備料/出餐)、成品物料卡、實際可用產量、狀態(草稿/發布)、發布時間 | 明細與步驟 |
| 食譜明細 | 版本、物料卡或半成品、用量、單位、重量類型(原重/淨重/熟重)、對應步驟 | 建立依賴圖 |
| 食譜步驟 | 版本、順序、標題、說明、媒體、計時秒數 | 連結明細 |
| 菜單規格 | 品牌/門店、菜單品項、規格、通路、售價、稅別、食譜版本與用量 | 套餐與包材 |
| 菜單包材 | 菜單規格、通路(內用/外帶/外送)、包材物料卡、數量 | 成本連動包材供應品價格 |
| 套餐 | 主餐、可選附餐/飲料池、加價、額外包材 | 組合由系統展開 |
| 成本快照 | 對象(食譜/菜單)、時點、成本、已知成本、狀態、缺口、使用的價格/換算/配方版本、**變動原因與差異行** | 永不改寫,供歷史與差異標記 |
| 待處理事項 | 類型、對象、系統判讀、依據、影響金額、狀態、處理結論、靜音範圍與期限 | 結論回寫各實體 |
| 變更紀錄 | 操作者、時間、對象、前後值、原因 | 全模組共用 |

**物料卡合併規則**

- 只有「同一種東西」才合併;規格不同(1 kg 包、900 g 包、整箱)可以合,各自保留換算
- 員餐帳戶(如上展＿員餐)的供應品也可併入同一物料卡;員餐與營業用的區分留在叫貨帳戶,不在物料
- 同名不自動合併,系統只提建議;跨品牌是否共用一張卡由人確認
- 合併後,成本基準價 = 主要供應品的現價換算成每基準單位;其他供應品價格供比價與跨廠商偵錯
- 統一料號(之後做):只改物料卡的顯示料號,舊代碼自動變別名,搜尋仍找得到,歷史叫貨單不改

## 計算規則

所有金額在服務端(DB view / RPC)算,前端只顯示;中間值保留 6 位小數,畫面顯示 2 位。

### 換算與產量

- 每基準單位成本 = 叫貨價 ÷ 該規格的基準單位量
- 行成本 = 用量(換成基準單位)× 每基準單位成本
- 半成品每單位成本 = 整批原料成本 ÷ **實際可用產量**;耗損已反映在產量裡,不再另加
- 用量要標明是採購原重、淨重或熟重;用淨重/熟重時必須有對應半成品或收率
- kg/g、L/ml 固定換算;g ↔ ml 必須是該物料的實測密度,不可預設 1:1;包/袋/箱/盒/罐/顆一律物料專屬
- 每行顯示換算鏈:`1 包 320 元 → 1 包 = 1,000 g → 0.32 元/g × 150 g = 48.00 元`
- 沿用現有 `recipe_conv` 與 `v_item_cost` 前,先核對實際單位,禁止對已換算的值再除一次

### 完整度

| 狀態 | 意思 | 正式成本/毛利 |
| --- | --- | --- |
| 完整 | 每一行都算得出(白名單零成本除外) | 顯示 |
| 缺價格 | 有行的物料沒有有效價格(單價 0 算缺) | 空白,另顯示已知成本 |
| 缺換算 | 用量單位換不到基準單位 | 同上 |
| 缺產量 | 半成品沒有可用產量 | 同上 |
| 循環引用 | A 引用 B、B 引用 A | 同上,且不可發布 |
| 超過深度 | 超過 5 層展開 | 同上,顯示錯誤不截斷 |
| 待重算 | 上游剛變、重算中 | 顯示舊值並標「待重算」 |

- 子食譜的缺口往上傳:即使菜單 9/9 行都對得到,只要任一半成品缺價就是不完整
- 白名單外的「不計成本」不算完整,進待處理(現有例:蔬菜高湯)
- 完整度與價格新鮮度分開顯示(例:「完整 · 價格最早 08-07」)

### 成本基準與歷史

- 成本 = 主要供應品**最近一次已確認的實際驗收進價** × 已發布配方;報價只供比價,不進成本
- 門檻內的變價立即生效(待確認);超過門檻的變價在確認前不生效
- 價格、換算、配方任一變動 → 依依賴圖重算受影響的半成品、食譜、菜單 → 每個對象寫一筆成本快照,記下「是哪一行、因為什麼變、變多少」
- 配方改動產生新食譜版本;價格改動不產生新食譜版本,只產生新成本快照
- 舊快照永不改寫
- 沒有入庫、盤點、結轉資料前,不提供加權平均實際存貨成本

### 稅別與指標

- 廠商價格保留原始含稅/未稅;成本比較時統一到同一稅別,不統一對所有廠商 ×1.05
- 月帳沿用既有規則(未稅廠商加總 ×1.05 四捨五入)
- 食材成本率 = 食材成本 ÷ 同稅別售價;含包材毛利率 = (售價 − 食材 − 包材) ÷ 售價
- 缺成本、未知稅別、售價 ≤ 0 時不算正式比率
- 外送通路貢獻試算的平台費率由管理者輸入,不猜
