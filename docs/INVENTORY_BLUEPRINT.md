# 進銷存藍圖（INVENTORY_BLUEPRINT）

> 2026-07-18 張良拍板方向：**地基先定、功能慢慢蓋**。
> 原則：之後難改的是「資料的形狀」，不是畫面。所有模組共用同一套資料，不各記各的。

## 核心公式（資料一致鐵則）

```
理論庫存 = 期初盤點 + 進貨（驗收完成的叫貨單） − 耗用（銷售×配方） − 報廢/耗損
差異     = 理論庫存 − 實際盤點   →  差太多 = 警報（漏記/浪費/流失）
明日備料 = 預估銷量（近期日均/週同日） × 配方 − 現有庫存
```

## 資料地基（4 件事）

| # | 地基 | 說明 | 現況 |
|---|---|---|---|
| 1 | 品項唯一 ID | 所有紀錄掛 `vendorItems` 的 id，不掛名字；改名不斷線 | ✅ 已如此 |
| 2 | 規格數字化 | 品項加 `packQty`（每件入數）＋`baseUnit`（基本單位：個/杯/g…）；庫存一律以基本單位計，「件」只是進貨包裝 | ❌ 階段 0 補 |
| 3 | 配方（BOM） | 銷售品項 → 原料耗用量（一杯咖啡＝豆 Xg＋杯×1＋蓋×1）；資料要張良/店長提供 | ❌ 階段 2 |
| 4 | 事實來源唯一 | 進貨事實＝**驗收完成**的叫貨單（sp_supply_pm_orders，含 check 驗收數）；銷售事實＝每日 POS（財務模組）。庫存永遠從這兩個算，不手記流水 | ✅ 兩邊已在抓 |

## 儲存架構注意

- 叫貨單目前整包一個 key（上限 600 張≈半年）。**開始做庫存前，叫貨單要改「一筆一檔」**（照 v1.6.0 交易/任務的逐筆存模式），庫存需要長期歷史。
- 盤點/庫存異動也逐筆存，永不覆寫，錯了用沖銷筆修正（同零用金帳本精神）。

## 分階段

| 階段 | 內容 | 前置 |
|---|---|---|
| 0 地基 | 品項加 packQty/baseUnit 欄；叫貨單改逐筆存 | 無，順手做 |
| 1 庫存表 | 手動盤點頁（期初/定期盤點）；進貨自動從驗收單累加 | 階段 0 |
| 2 備料清單 | 配方表（可自訂增刪改）；明日備料＝預估銷量×配方−庫存 | 張良提供配方 |
| 3 自動核對 | 理論 vs 盤點差異警報；D 哥主動推播異常 | 階段 1+2 跑順 |
