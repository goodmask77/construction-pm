## A. 兩稿怎麼取用
- **A 取骨架**：會員、消費、點數帳本、券、原子交易；丟掉「不做遊戲」、一次包辦所有 P0、另換 React／Edge Functions 的假設。
- **B 取安全要求**：Provider 身分、獨立行銷同意、規則快照、抽獎冪等、庫存／預算、停用與測試；丟掉大而全表系統、推薦任務、遊戲延至 P2 的排序。
- **最終以 A 縮編＋B 活動模型為底，10 張真表**：`members`、`member_identities`、`member_brands`、`visits`、`point_ledger`、`coupon_templates`、`coupons`、`campaigns`、`draws`、`events`。
  - `events` 分類保存同意、稽核、webhook 去重／通知任務。
  - 品牌、門市、點數設定先沿用版本化 KV；活動獎池存在 campaigns，DB 鎖定更新；draws 同時保存資格來源與結果。
  - UUID 主鍵、品牌隔離；建立 migrations，不搬動員工資料。

## B. 遊戲：第一期可以做
- **最小版：一個轉盤活動、三種低價獎＋未中獎**。拉霸下一批加，兩者共用同一抽獎 API。
- **固定槽位優先**：預先設定各獎數量及空獎；伺服器安全亂數抽剩餘槽位。資格驗證、扣槽、存結果、發券在同一 DB transaction；重送返回原結果。
- 權重法暫不用：缺貨後如何重分配機率容易說不清。固定槽位須公告初始數量、機會會隨剩餘獎池改變；額滿停止，不偷偷補空獎。
- 第一期採**每活動每會員一次、免費參加**；比每日一次省預算、防刷。第二批改「已驗證消費一單一抽」，不販售抽獎次數、不收下注、不兌現。
- 獎品先用折扣券／免費小點券；點數獎等帳本完成再加。以**市價而非食材成本**計獎品價值。
- 前端用 CSS 旋轉＋固定落點；後端先保存結果再播放，斷線可查回。動畫不決定獎項。

**法規與稅務**
- 舊《事業提供贈品贈獎額度辦法》已廢止，不能照舊額度表當現行義務；仍須遵守公平交易法的不實廣告等規定，公告資格、期間、數量、領獎限制與效期。
- 「單次 1,000 元以上就申報」不精確：境內居住者，**同一給付單位全年給付合計不超過 1,000 元**，才有免列單規定。
- 境內居住者機會中獎扣繳率 10%；每次應扣稅額不超過 2,000 元免扣，常見活動寫法為 **20,010 元以上扣繳**。非居住者通常為 20%，不能套同一門檻。
- **最省事：單獎市價 ≤300 元，同一法律實體對同人全年機會中獎合計 ≤900 元**，跨活動合併追蹤；正式公告前由會計師確認獎品性質與當期規定。本回答未即時查核 2026 法規。

## C. 員工系統怎麼沿用
- 複用商城／存摺 UI、規則管理、排行榜計算概念；抽出共用元件與純函式。
- **不可直接沿用 `awardPts` 的 KV 寫入、員工帳本或主管審核扣點流程**；客人獨立資料、權限、交易函式，禁止跨庫讀寫。
- 客人商城先一項固定獎勵；排行榜第二期才做**自願加入、匿名暱稱、月榜**，不要公開消費金額。
- 等級先基本會員；累積可靠消費資料後做兩級即可，依淨消費升級，不靠遊戲點數。

## D. 六個分歧最終立場
- A：UUID＋Provider／LINE 身分表；合併須人工驗證。
- B：會員主檔與流水都用真表。
- C：店員掃 60 秒會員 QR→選獎→核銷時原子扣點。
- D：第一期要有一項固定兌換，形成閉環。
- E：指定店員輸 POS 單號＋金額，限額留痕；不宣稱已串 POS。
- F：手打名字不給點；只給已驗證 owner，共用品項歸屬由老闆定，不硬套 50%。

## E. 每批一個 PR
1. **入會＋遊戲閉環**：migration、LIFF、告知／同意、券夾、轉盤、店員核銷；擴充原 inbox webhook 的 follow／unfollow，不改網址。老闆能親自入會、抽獎、兌小點。
   - 驗收：錯 channel 拒絕；雙擊只抽一次；最後一獎併發不超發；斷線查回；同券雙機只成功一次；無權店員不能核銷。
2. **集點＋一項兌換**：現場單號入點、團訂已收款入點、存摺、退款反向流水；驗收重送十次只入一次、並發不超扣。
3. **營運擴充**：拉霸外觀、生日券、對帳、基本報表；再評估等級／月榜／分眾。

- 每 PR 附 Preview、測試證據、操作指南，等老闆說 merge。
- 老闆先給：**同 Provider 的 LINE Login channel／LIFF ID**、法律實體、三種獎品與數量／效期／總預算、指定核銷店員；第二批前定集點比例、兌換門檻及退款政策。未定只開測試白名單。

## F. 最該提醒的三件事
1. **一個 LINE 帳號不等於一個自然人**；低價、限次、總預算才是第一道防線。
2. **沒有逐筆 POS 對帳，就不是自動可信的消費 CRM**；尖峰操作時間必須實測。
3. **遊戲參與不等於回購**；先看獎券核銷後的再次消費，且不為每次抽獎／賺點發 LINE push。
