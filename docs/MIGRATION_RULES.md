# 搬遷鐵則：GD／Belle／阿桑／小夏 → 新殼 abgd（張良 2026-10-14 定，不可再犯）

背景與討論紀錄：docs/REBUILD_SAAS_3AI_2026-10.md（三家五輪）。
每次動到「要搬或已搬」的功能，開工前先讀這份。

## 一、一個功能，同一時間只在一邊改

| 功能狀態 | 在哪邊改 | 說明 |
|---|---|---|
| 還沒排到搬 | **只改 GD**，照常加功能 | 之後照最新版搬，只搬一次 |
| 搬遷中（排進這幾週） | 兩邊都要改（見第二節），或先記下等搬完 | 盡量縮短這段時間 |
| 已搬、入口已切到新殼 | **只改新殼** | GD 那份不再碰 |

- 「入口切過去」＝GD 側欄按鈕還在，點下去打開新殼的頁面；夥伴看到的就是新殼。

## 二、為什麼兩邊改會漏（不可再犯的原因）

1. 同一功能兩邊寫法、檔案位置不同，改的時候要靠「記得另一邊在哪」。
2. AI 每個對話的記憶是分開的，上次改了什麼下次不一定記得。
3. 兩邊驗證方式不同，容易測一邊就當兩邊都好。

## 三、防漏三件事（必做）

1. **功能對照表** `docs/FEATURE_MAP.md`：每個功能一列，寫「GD 位置／新殼位置／目前負責的一邊／狀態」。改任何功能前先查表，不靠記憶；搬完或切入口當天就更新表。
2. **PR 閘門**：改到「搬遷中」的功能，PR 必須同時改兩邊，PR 說明列出兩邊改了哪裡；少一邊不准合併。
3. **自動比對**：搬遷中的功能要有對帳腳本，同一份資料丟進新舊兩邊，結果（筆數、金額、狀態）完全一致才算過；不一致就擋下。

## 四、資料同步

- **新殼用自己的新表**（有公司欄位＋權限牆），不讀寫 GD 的舊大表 pm_documents。
- **單向同步**，同一份資料同一時間只有一邊能寫：
  - 搬之前：GD 寫 → 抄到新殼（新殼只讀，用來比對）。
  - 切換後：新殼寫 → 抄回 GD（讓 DD 和還沒搬的舊頁讀得到）。
  - 全部搬完：關掉同步。
- 不做雙向同步：原因是兩邊同時改的衝突、互相觸發的無限循環、舊表整包覆蓋洗掉別人改的欄位。既然同一時間只有一邊寫，雙向本來就用不到。
- 同步必做：防重複（同一筆不寫兩次）、防舊蓋新（看版本或更新時間）、刪除也要同步、差異自動通知。
- 寫回舊表只改有變的欄位，不整包覆蓋。
- 切換順序：停寫 → 追平 → 對帳 → 反轉方向；退回時也不能變成兩邊同時寫。

## 五、檔案與資料搬家

- 資料庫備份不含上傳檔案，檔案要另外整批複製。
- 一律先把所有檔案下載到本機一個資料夾當備份 → 新殼建好再整批補上 → 核對檔案數量與大小一致才算完成。
- 數字對帳：用原系統自己的算法算，跟原系統畫面上的數字差 0 元才算完成；對不上不准回報完成。

## 六、程式庫整潔

- 一次性的腳本放暫存區，不進程式庫；會重複用的才進 `scripts/`。
- 已合併的分支定期清掉（2026-10-14 已清 87 條）。
