## 三家各自抓到的重點（非共識但有價值）
- **Claude 抓到現有程式漏洞**：`custWho` 驗 LIFF token 只看 `client_id` 存在、沒比對是自家頻道 → 任何 LINE Login app 的 token 都過關。**已修**（env `LINE_LOGIN_CHANNEL_ID` 設了就鎖）。
- **ChatGPT**：計價圖（姓名／電話／統編）不要丟永久公開圖庫，用有限期連結；後端要重算、不信前端小計；兌換時存獎勵名稱／點數快照；serverless 背景工作要用 DB 工作紀錄＋cron；點數負債只是管理估算要跟會計師確認；通知失敗不回滾點數（outbox 重試）。
- **Gemini**：QR 截圖轉傳風險→60 秒效期；兩個訂單同時完成的併發超發；LINE 封鎖率（推播太多客人封鎖＝失去唯一聯繫管道）。
- **Claude**：Rich Menu 是帳號層級，GD／AB 兩帳號是一套點數還是兩套要先定（影響主鍵）；LIFF 在 LINE 外部瀏覽器開要有降級頁。

## 第一期（M1）三家交集＋CC 建議
1. Supabase 真表：`members`（UUID 主鍵）、`member_identities`（LINE uid→member）、`member_pts`（流水＋idem_key UNIQUE）、`member_redeems`；設定留 KV `pm_member_cfg`（有版本號）。
2. 入會只走 LIFF 會員卡頁（告知文字＋同意版本；手機選填）；follow 只 reply 歡迎。
3. 賺點：團訂「完成且已收款」入點（LINE 身分者依自己小計，共用歸主辦人）＋現場「店員輸 POS 單號＋金額」（限主管／指定店員、單筆上限）。
4. 用點：一項固定獎勵，店員掃客人 QR（60 秒）→選獎勵→核銷才扣點。
5. /prep「會員」分頁：搜尋、每人流水、手動加扣點（留痕＋上限）、核銷、必要設定（累點比例、獎勵一項）、權限分權。
6. LIFF `/member`：點數、流水、QR、更正手機、退會。
7. 通知：只有「首次入點」與「核銷成功」push；其餘頁面顯示。
8. 驗收門檻（ChatGPT 版）：同一訂單重送十次只入一次；同餘額同時核銷兩次不超扣；退款有反向流水；過期 QR 拒絕；LINE 失敗不影響點數。
